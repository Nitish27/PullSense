# Plan: GitHub-Connected Setup Health

**Goal:** Turn the local setup center into a safe GitHub-connected onboarding surface that shows whether PullSense is installed and which repositories it can inspect.
**Phase:** E / GitHub-connected onboarding
**Requires:** `.planning/plans/01-10-PLAN.md`
**Provides:** A polished setup label, a read-only installation-health API, and repository discovery in `/settings`.

---

### Task 1: Polish The Setup Center Context

**Files:**
- Modify: `apps/web/app/settings/page.tsx`

**Action:**
Replace the inherited global Phase 0 label with setup-specific language so the settings page accurately represents its role. Preserve the current visual design and server-rendered implementation.

**Done when:**
- [x] `/settings` presents setup and onboarding context rather than Phase 0 foundations.

---

### Task 2: Add Safe GitHub Installation Discovery

**Files:**
- Create: `packages/github/src/installation-health.ts`
- Create: `packages/github/src/installation-health.test.ts`
- Modify: `packages/github/src/index.ts`
- Create: `apps/api/src/routes/github-installations.ts`
- Create: `apps/api/src/routes/github-installations.test.ts`
- Modify: `apps/api/src/app.ts`
- Modify: `apps/api/src/server.ts`

**Action:**
Use the existing GitHub App credentials to read the App's installations and each installation's accessible repositories. Normalize only safe metadata: installation id, account login, repository selection, repository owner/name/full name, visibility, and GitHub URL. Do not return tokens, private keys, or any secret.

Expose this through a read-only API route. Return a deliberate missing-credentials state if app credentials are not configured. Return a clear unavailable error when GitHub cannot be reached or rejects the credentials. Use injectable clients/listers so the helper and route are fully unit-tested without live network calls.

**Done when:**
- [x] The API can report GitHub App installations and accessible repositories through a safe read-only response.
- [x] Missing credentials and GitHub failures have distinct, actionable states.
- [x] Tests confirm secrets are never serialized.

### Task 3: Surface Installation Health In The Setup Center

**Files:**
- Modify: `apps/web/src/review-runs.ts`
- Modify: `apps/web/src/review-runs.test.ts`
- Modify: `apps/web/src/setup-center-view.tsx`

**Action:**
Load installation health server-side from the local API and show a dedicated GitHub connection panel in `/settings`. It must distinguish connected installations, no installations, missing credentials, and unavailable GitHub access. Link each accessible repository to its existing repository-health route, and design the panel for desktop and mobile.

Keep the local configuration readiness cards; this addition clarifies the difference between configured credentials and a verified GitHub connection.

**Done when:**
- [x] A tester can see whether the App is installed and which repositories it can access.
- [x] Repository links open existing PullSense repository health pages.
- [x] Empty and unavailable states are clear and non-sensitive.
- [x] `pnpm lint`, `pnpm typecheck`, `pnpm test`, and `pnpm build` pass.

---

## Constraints

- Read-only GitHub access only.
- No new dependencies or environment variables.
- No credential, token, or private-key exposure.
- Live GitHub calls occur only from the dedicated installation-health endpoint.
