# Plan: Repository Health And Operations Visibility

**Goal:** Turn persisted PullSense review runs into a repository-level health dashboard with real review outcomes, latency, provider-failure trends, and recent PR activity.
**Phase:** C / repository health and operations visibility
**Requires:** `.planning/plans/01-08-PLAN.md`
**Provides:** A repository health API and a dedicated web route at `/repositories/[owner]/[repository]`.
**Context budget:** 3 tasks, approximately 90 minutes total

---

### Task 1: Add Repository Health Aggregation And API Contract

**Files:**
- Modify: `apps/api/src/db/review-runs.ts`
- Modify: `apps/api/src/db/review-runs.test.ts`
- Modify: `apps/api/src/routes/review-runs.ts`
- Modify: `apps/api/src/routes/review-runs.test.ts`

**Action:**
Add a repository-scoped read model without changing the `review_runs` schema. The query must return a bounded recent window of runs, aggregate total/success/failed counts, compute average completed-review latency from runs that have both timestamps, classify stored failure text as Gemini, GitHub, database, queue, or unknown, and return the newest run for each PR number.

Expose `GET /repositories/:owner/:repository/review-health`. Validate non-empty route parameters and return an additive JSON response containing `owner`, `repository`, `metrics`, `failureTrends`, and `recentPullRequests`.

Do not fetch GitHub from this endpoint, add a migration, leak raw database errors, or return unbounded history. Keep the existing PR review-runs endpoint unchanged.

**Verify:**
```bash
pnpm --filter @ai-code-review/api test -- --config vitest.config.ts src/db/review-runs.test.ts src/routes/review-runs.test.ts
pnpm --filter @ai-code-review/api typecheck
```

**Done when:**
- [ ] Aggregation metrics are calculated from persisted review-run rows.
- [ ] Failure categories are deterministic and tested.
- [ ] The endpoint returns repository-scoped metrics plus recent PR records.
- [ ] Invalid repository parameters return a structured client error.

---

### Task 2: Add Web Repository Health Data Layer And Route

**Files:**
- Create: `apps/web/app/repositories/[owner]/[repository]/page.tsx`
- Modify: `apps/web/src/review-runs.ts`
- Modify: `apps/web/src/review-runs.test.ts`

**Action:**
Add repository-health types, a server-side loader, and internal path builders beside the existing review-runs data utilities. Reuse the existing `no-store` fetch behavior and error-state shape. The route must obtain `NEXT_PUBLIC_API_BASE_URL` through `getWebEnv` and pass page data to a dedicated view component.

Do not introduce client-side data fetching, a new environment variable, or a second API client abstraction. Invalid route values and API failures must render through the same explicit state model used by the PR detail route.

**Verify:**
```bash
pnpm --filter @ai-code-review/web test -- review-runs.test.ts
pnpm --filter @ai-code-review/web typecheck
```

**Done when:**
- [ ] A repository route resolves owner and repository parameters.
- [ ] The loader requests `/repositories/:owner/:repository/review-health`.
- [ ] Success, invalid-route, and API-failure states are covered by tests.

---

### Task 3: Build The Repository Health Dashboard

**Files:**
- Create: `apps/web/src/repository-health-view.tsx`
- Modify: `apps/web/src/review-runs-dashboard.module.css`
- Modify: `apps/web/src/review-runs-ready-state.tsx`
- Modify: `apps/web/src/review-runs.test.ts`

**Action:**
Build a desktop and mobile-friendly repository health surface using the existing PullSense visual system. Show health metrics, latency, provider failure trends, recent PR cards, and clear empty/error states. Each recent PR must link to its existing dedicated PR detail route. Add a repository-health link from the loaded PR dashboard/detail experience so the new route is discoverable.

Do not add charts that require a dependency, hard-code product metrics, hide failures behind interaction, or replace the current PR command-center experience. Use the existing CSS module, typography, badge, card, and `next/link` patterns.

**Verify:**
```bash
pnpm --filter @ai-code-review/web lint
pnpm --filter @ai-code-review/web typecheck
pnpm --filter @ai-code-review/web test
pnpm --filter @ai-code-review/web build
pnpm lint
pnpm typecheck
pnpm test
pnpm build
```

**Done when:**
- [ ] Repository health displays real API values and recent PR links.
- [ ] Failure categories and latency remain visible without drilling into a PR.
- [ ] The route has a designed no-data and API-error state.
- [ ] Web and workspace verification commands pass.
